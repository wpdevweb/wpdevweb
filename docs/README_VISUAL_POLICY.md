# Profile README visual policy (candidate v2.1)

The established `dashboard.snapshot.json` remains the ONLY source for public numeric claims; this pilot does not refresh or change the Sept 03 baseline. README and the light/dark repo-local SVG banners are generated by `npm run render` and verified by `npm run verify` (including a drift canary and malicious media payload fixtures).

- Theme system: serif editorial hero, local static SVG `<picture>`, a single native Mermaid engineering loop, compact functional tables, explanatory ASCII view and a dated roadmap; no fake GIFs, dynamic badges, remote hero services or base64/data URIs.
- Performance: max ~16 KiB per SVG; no client requests attributable to external README assets; no npm runtime dependencies; GitHub SVG security/rendering is platform-controlled, and final rendered light/dark appearance still needs browser review before merge.
- Accessibility: meaningful alt and SVG title/desc, headings and text outside the hero, text-only fallback in `<details>`, safe contrast. SVG ornament never carries unique operational information.
- Trust: clear split between historical snapshot, implementation principles, proposed stages and observed release. Private repository names and workload topology are forbidden in public content.
- Changes: source snapshot first for numeric updates. Decoration may evolve separately but never override the generated contract. Only writer-scoped PRs and independent review; no automatic main updates.

For private repos with different policies use the separate fleet design contract; do not blindly reuse this profile's security restrictions on repo-local scripts or private badges.
